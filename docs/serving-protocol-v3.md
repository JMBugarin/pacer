# Serving protocol v3 — frozen before new workload generation

Scope: local synthetic-token replay on Apple M5 Pro, Qwen3-0.6B-4bit, MLX 0.32.4 / mlx-lm 0.32.2. No production or human prompt data. Existing model/policy parameters remain fixed (Pacer mult=1, k=32, reuse=4; models/fast_traceA.json). No retuning on final results. Previous Qwen test hour is development data.

Correctness: matched-shape pooled/stock logits must be bitwise equal on development controls; full/cached agreement target remains >=99% over all eligible observations, with finite logits and max absolute error <1 as a separate development bound. A numerical near-tie is still a behavioral mismatch. Cached experimental output is not certified for token-equivalent serving. Verified-output mode recomputes full prefill on every hit and returns its logits, charging that work to TTFT. It trades away caching gains for reference-output fidelity and does not establish production serving readiness.

Final workload: generated only after this protocol and generator are committed. 120 requests with 12 equally likely synthetic prefix sessions, 16 shared blocks and 1–8 unique suffix blocks, 16 output tokens, arrivals spaced 1s, seed 20261115. No test-set tuning. Hash every generated file/model/snapshot and preserve machine/dependency versions. Cache 20% of unique blocks, tpot=.002, chunk=2048. Four paired repeats with alternating LRU/Pacer order (existing rotation), one fixed warmup of first 30 requests. Use --verified-output, --check 100, --boot 2000. Preserve every run including failures; no best-run selection.

Report per-repeat request p50/p95 TTFT, hit ratio, prefill work, and paired mean latency difference. Uncertainty unit is repeat, not request: report all four paired differences and their min/max; four pairs do not justify a robust generalization claim. Existing request-bootstrap output is descriptive only and must not be represented as accounting for run drift. Eviction timing is measured separately using the existing overhead script; TTFT includes gather/forward/reference verification, not controller eviction. No combined end-to-end serving claim. CPU contention and local VM presence disclosed; no separate server/network.

If code changes after final exposure, version protocol and use new final seed/data. Negative results remain published. This is an independent newly generated synthetic workload relative to earlier tuning, not independent external review or a real-user serving workload.
